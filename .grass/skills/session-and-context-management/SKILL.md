# 会话与上下文

## 一、上下文满了怎么办

GrassAgent 会自动压缩：旧消息总结成结构化摘要（目标、约束、进展、决定、
验证记录、下一步），发给模型的内容变成「摘要 + 最近一段」。

**压缩只改发给模型的视图，不改历史**——完整对话还在库里。

想手动压：

```
/compact
/compact 保留验证记录和每个决策的理由
```

参数是给摘要的额外要求。压缩掉的只能是**过程**，不能是**依据**：
什么检查跑过、什么失败了、为什么失败，丢了模型就会推翻既定决策或者重犯旧错。

**长对话变草率是信号**：任务前期它仔细核对，后期开始做完一步就宣布完成。
这时候别靠"提醒它认真点"，靠结构——把大任务拆成几个小会话，
或者主动做 checkpoint 把依据落成文件。

## 二、跨会话记住东西

会话是隔离的。换会话、退出重开，之前说的话就没了。
要把结论留住，得**落成文件**：

| 放哪 | 放什么 |
| --- | --- |
| 项目规则文件 | 长期有效的约定、流程、完成条件 |
| 状态文件 | 进度、数据、决策及理由 |
| 笔记文件 | 排查过程中的发现、用户的偏好 |

判断标准：**下次开新会话还需要它吗**。需要就落文件，不需要就留在对话里。

## 三、会话操作

| 命令 | 作用 |
| --- | --- |
| `/sessions` | 列出所有会话 |
| `/resume <会话ID>` | 切到别的会话（不带参数会弹选择器） |
| `/new` | 开一个新会话 |
| `/clear` | 清空当前对话，保留会话 |
| `/export [路径]` | 导出成 JSON 包，换机器再导回来 |
| `/import <路径>` | 导回会话（`--replace` 才覆盖同 ID） |

## 四、导出要注意的

- 导出前会先 sync，最后一轮还在内存里，不 sync 带走的是旧对话
- 导入后要重新载入，别拿旧的上下文去 sync，会把刚导进来的盖掉
- 包里**只有对话**，没有 API Key，也不会有钩子被写回去
- `tool_call` 和 `tool_result` 配不上对的会话会被拒绝——宁可导不进来，
  也不要导进来之后下次请求直接 400

## 五、上下文预算

上下文是花钱的资源，别当档案柜：

- 入口只放**索引**（路径 + 一句话摘要），用到再读
- 工具输出已经截断过了：读文件超 200 行只给尾部，命令输出超长也只给尾部，
  全文在临时文件里，需要就按提示去读
- 不确定该不该给的东西，问一句："这段不给，它会做错决策吗？"
