# 长任务：后台跑 + 定时看 + 跑完验收

短命令用 `run_bash` 就够了。超过一分钟的命令不要占着回合等——
回合在等的时候什么都干不了，超时了还前功尽弃。

## 一、选报告方式

| 情况 | 做法 |
| --- | --- |
| 想知道中途长什么样（构建、训练、压测） | `monitor` + `afterMs`，中途报一次「还在跑」 |
| 只要最终结果，等多久都行 | `monitor` + `timeoutMs`，结束时报 |
| 就想现在看到，等不了 | `monitor` + `wait: true`，最多等 60 秒 |

```jsonc
{ "kind": "command", "command": "npm run build", "afterMs": 120000, "timeoutMs": 600000 }
```

`kind` 还有 `timer`（纯定时提醒）和 `sandbox`（看沙盒还在不在、连不连得上）。
远程沙盒不支持 `kind: "command"`，只能用 `run_bash`。

## 二、报告是怎么回来的

后台报告**不是** `tool_result`——产生它的那次工具调用早就返回了。
它作为一条带 `[monitor]` 标记的 user 消息进上下文，然后开新的一轮。

所以：

- 报告到达时如果正在跑回合，会先排队，等这一轮结束再开新的，不会插进来打断
- 同一时刻最多 8 个监视器，一个最多报 3 次
- 会话结束（Ctrl+C、stdin 读完）监视器全部取消，后台命令一起被杀
  ——监视器不活在会话之外，别指望退出后还能收到报告

## 三、跑完不算完，要验收

`exit 0` 只说明命令没崩，不代表结果对。结束报告到手之后：

1. **读输出尾部**，不是只看退出码。`npm test` 退出码 0 也可能有测试被 skip
2. **确认产物真的在**：`ls -la dist/` 看时间戳，别信命令自己的 echo
3. **该跑的就跑**：改了源码就跑 `npm run typecheck` 和 `npm run test:unit`，
   光跑被监视的那一条不够

## 四、常见坑

- **报告被丢弃**：会话结束时排队的报告会丢掉。想留住就别在这时候退出
- **命令一直不结束**：`timeoutMs` 是硬上限，到点直接杀。给够时间，别用 0
- **输出太长**：后台只留 8 KB 尾部，报告里再截到 2 KB。要完整输出就另跑一次
  带重定向的命令，再 `read_file` 读文件
- **并发写同一个文件**：后台命令写文件不受 `mutatesFiles` 排队管，它什么时候写
  是它自己的事。有冲突就别并发跑
